# V2.1.22 Investigation Notes

## Bug 1: Address auto-fill format error
**Screenshot**: pasted_file_1C1W9l_image.png shows:
- Address Line 1 contains: "Jalan Menglembu Utara 1 Menglembu Ipoh, Perak, 31450, Malaysia" (everything in one line)
- Address Line 2: empty
- City/Region: empty
- State: empty
- Postcode: empty
- Country: Malaysia

**Problem**: When customer address is synced from customers table, all address components are concatenated into addressLine1. System needs to parse and split into:
- addressLine1: street address (e.g., "Jalan Menglembu Utara 1")
- addressLine2: area/neighborhood (e.g., "Menglembu")
- City: city (e.g., "Ipoh")
- State: state (e.g., "Perak")
- Postcode: postcode (e.g., "31450")
- Country: country (e.g., "Malaysia")

**Root cause**: The customer's `address` field in the customers table stores the full address as a single string. When OrderCreatePage or OrderEditPage selects a customer, it puts the entire address into `shippingAddress` (which maps to addressLine1).

**Fix needed**:
1. Backend: When syncing address from customer to order, parse the full address string and split into structured fields
2. Or: Store structured address in customers table (addressLine1, addressLine2, city, state, postcode) and use those directly

**Current customers table fields**: address, addressLine1, addressLine2, city, state, postcode, country (added in V2.1.21)

**Current orders table fields**: shippingAddress (maps to addressLine1), addressLine2, shippingCity, shippingState, shippingPostcode (added in V2.1.21), shippingArea, shippingCountry
