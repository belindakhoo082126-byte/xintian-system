# Dashboard 与报告菜单统计口径审计

审计日期：2026-08-12  
范围：Dashboard 本月营业额，以及「报告」菜单下的七个分菜单。  
结论：目前这些页面**并非全部使用同一套“已汇款金额”口径**。它们分别用于订单金额、应收款、库存、成本、损耗和经营概览，因此出现不同数字是当前实现的预期结果；但 Dashboard 的名称容易让人误解为实收款，且第七项菜单名称与实际页面不符。

## 一、Dashboard 是否等于已汇款订单金额？

**不是严格的“已汇款／实收金额”。**

Dashboard 的「本地销售额／中国代购销售额」按**订单建立日期**统计，并将以下订单状态的 `totalAmount` 相加：`receipt_uploaded`、`packing`、`partial_shipped`、`shipped`、`completed`。这里使用的是**订单总额**，即商品金额加运费等订单金额，不是 `paidAmount`。

因此，它有两个重要特点：

1. `receipt_uploaded` 代表客户已上传付款凭证、仍可能等待审核；它已被 Dashboard 计入营业额，却不等于付款已经审核确认。
2. `partial_payment` 即使已有部分实收款，也不在 Dashboard 的状态白名单内；反之，已进入 `packing` 的订单会以订单总额计入，即使 `paidAmount` 和总额不同。

> Dashboard 当前更准确的名称是：**“本月符合处理状态的订单总额”**，而不是“本月实收款”。

### 截图数额的实际构成（2026-08-01 起建立的非会员订单）

| 订单类别／状态 | 订单数 | 订单总额 `totalAmount` | 已记录付款 `paidAmount` | 是否计入 Dashboard 本月销售额 |
|---|---:|---:|---:|---|
| 本地／`packing` | 10 | RM2,562.00 | RM2,703.00 | 是 |
| 本地／`receipt_uploaded` | 1 | RM98.00 | RM100.00 | 是 |
| 本地／`shipped` | 4 | RM647.00 | RM691.00 | 是 |
| 本地／`partial_payment` | 1 | RM251.00 | RM90.00 | 否 |
| 本地／`pending` | 8 | RM2,878.00 | RM0.00 | 否 |
| 中国代购／`pending` | 5 | RM688.00 | RM0.00 | 否 |

所以截图中的 Dashboard 本地销售额为 **RM3,307.00**：

`RM2,562.00 + RM98.00 + RM647.00 = RM3,307.00`

## 二、七项报告目前各自的逻辑

所有报告的预设日期范围均以页面查询时的日期计算；「本月」为当月第一天 00:00 至当天 23:59:59。除非另有说明，订单类报表用的是**订单建立时间 `createdAt`**，不是客户付款时间。

| # | 菜单名称 | 当前统计对象与日期 | 主要金额／公式 | 是否等于已汇款金额 |
|---|---|---|---|---|
| 1 | 销售与收款 | 选定期间内建立的所有非会员订单 | 商品销售额 = `SUM(physicalSubtotal)`；已收款 = `SUM(paidAmount)`；未收款 = `SUM(totalAmount - paidAmount)` | **只有“已收款”卡是订单当前已记录付款的汇总**；但仍按订单建立日归类，不是付款发生日 |
| 2 | 商品销售 | 选定期间建立、未取消的实体商品订单项 | 销量 = `SUM(quantity)`；销售额 = `SUM(order_items.subtotal)` | 否；包含尚未付款的未取消订单 |
| 3 | 客户消费 | 选定期间建立、未取消的非会员订单，按客户汇总 | 消费额 = `SUM(totalAmount)`；已付 = `SUM(paidAmount)`；欠款 = `SUM(totalAmount-paidAmount)` | “已付”是订单当前付款累计；“消费额”不是实收 |
| 4 | 进货与库存 | 进货按 `purchase_date`；库存为当前 active 批次快照 | 进货额 = `SUM(purchase_orders.totalAmount)`，目前草稿单也包含；库存价值 = `SUM(remaining_quantity × unit_cost)` | 否；这是采购和当前库存成本，不是销售或收款 |
| 5 | 利润分析 | 销售按订单建立日；成本／运费／退款按各自业务日期 | 实际毛利 = 商品销售额 − FIFO 商品成本 + 运费收入 − 实际运费成本 − 报废损失 − 退款 | 否；这是经营利润口径，未以是否付款为条件 |
| 6 | 损耗分析 | 选定期间建立的库存调整记录 | 损耗数量 = `SUM(ABS(quantityChange))`；损耗成本 = `SUM(totalCost)`；损耗率 = 损耗数量 ÷ 当前实体库存 | 否；只统计库存异常、报废等成本损耗 |
| 7 | Payment Record（当前菜单文字） | 实际打开的是「经营总览」，不是付款流水 | 汇总订单额、订单当前已付金额、欠款、退款、FIFO 成本、固定包裹成本估算、毛利及多个 TOP10 | **不是 Payment Record**；其中“已汇款金额”是 `SUM(paidAmount) - 当期退款`，仍按订单建立日筛选 |

## 三、为什么「销售与收款」截图与 Dashboard 不一样？

截图中的「销售与收款」采用的是全部 29 张当月建立、非会员订单的订单台账，因此它显示：

| 指标 | 截图金额 | 含义 |
|---|---:|---|
| 商品销售额 | RM6,803.00 | 所有订单的商品小计，含本地待付款、中国代购待付款与部分付款订单；不含运费 |
| 已收款 | RM3,584.00 | 所有这些订单当前 `paidAmount` 的总和，包含部分付款及多汇款后的已记录金额 |
| 未收款 | RM3,540.00 | 所有这些订单的 `totalAmount - paidAmount`；会包含待付款订单，也会受少付／多付影响而出现正或负余额 |
| 订单数 | 29 | 所有当月建立、非会员订单 |

Dashboard 的 RM3,307.00 则只取上述订单中已进入指定处理状态的**订单总额**，并且包含运费。因此它不应与「商品销售额」RM6,803.00 或「已收款」RM3,584.00直接比较。

## 四、目前需要注意的三个口径问题

1. **实收日期问题。**销售与收款、客户消费和经营总览都以订单建立日筛选，再读取订单当前累计 `paidAmount`。例如 7 月建立、8 月才付款的订单，不会出现在 8 月“已收款”中；它会改变重新查询 7 月报表后的结果。因此目前“已收款”更像“该批订单截至现在的累计已付”，并非会计意义上的“本期实际收款”。
2. **取消订单问题。**商品销售、客户消费、经营总览与利润分析排除了取消订单；销售与收款明细目前没有排除取消订单。若有已取消订单，销售与收款会与其他报表进一步不一致。
3. **第七项菜单名称问题。**菜单写作 `Payment Record`，但路径打开的是「经营总览」。真正的付款流水页应按每笔付款记录的付款日期、审核状态、方式与关联订单统计；当前页面并不是这种逐笔付款流水。

## 五、建议统一方向（需确认后才修改）

建议保留不同报表的业务用途，但为每一项明确标签和单一数据口径：

| 页面／指标 | 建议统一定义 |
|---|---|
| Dashboard「本月销售额」 | 改名为「本月已确认订单额」，或改用已审核付款流水的实收金额；两者二选一并全系统一致 |
| 销售与收款 | 保留“订单台账”，明确分为订单额、当前累计已收、当前欠款；取消订单排除或单列 |
| Payment Record | 改名为「经营总览」；若需要付款流水，应新增真正的「付款记录」页面，按付款审核／付款发生日期统计 |
| 商品、客户、利润报表 | 保持各自销售／客户／成本用途，但在标题标记“按订单建立日”或“按库存／退款业务发生日” |

在未得到确认前，本次仅完成审计说明，**没有修改任何金额、订单、付款或报告计算逻辑**。
