# CN／IB 端到端隔离演练报告

**演练日期：** 2026-08-12（马来西亚时间）  
**演练范围：** 中国代购直播、商品三阶段数量、CN自动建立IB、汇款期限超期处理、IB锁定审计，以及自动IB通过关联CN读取订单。  
**演练方式：** 因后台管理员会话无法登录，本次使用与生产相同的数据库访问层和服务函数进行真实隔离演练。演练数据统一带有 `QA-CNIB-E2E-` 标识，测试结束后按照外键依赖逆序自动清理。

## 演练数据设计

演练建立一名QA客户、一个QA商品和三场已结束的中国代购直播。三场直播均销售同一个商品，以验证跨场次以商品ID合并的规则。随后建立三笔中国代购订单：一笔已确认全额汇款（数量2）、一笔未汇款且无凭证（数量3），以及一笔已上传、仍待审核的付款凭证订单（数量4）。CN结束日期设定在过去，因而其默认汇款期限已过，能够测试自动超期处理。

| 验证项目 | 预期结果 | 实测结果 |
|---|---|---|
| 按日期选择中国代购直播 | 找到所选日期范围内的3场直播 | 通过；查询按日期倒序显示3场QA直播。 |
| 跨场次商品合并 | 同商品ID合并为一行，并显示三场贡献 | 通过；直播场数为3。 |
| 三阶段数量统计 | 已下单=7，已汇款=2，已完成=0，且互不重复 | 通过。未汇款3和待审核凭证4进入已下单；已确认全额汇款2进入已汇款。 |
| CN创建与订单关联 | CN绑定3笔所选直播的有效中国代购订单 | 通过；3笔订单的 `importBatchId` 均绑定至CN编号。 |
| 自动建立IB | CN创建后自动产生关联IB | 通过；IB的 `cnId` 指向CN，初始状态为 `in_progress`（等待到货）。 |
| 默认汇款期限 | `paymentDeadline = CN结束日期 + 2天` | 通过。 |
| 超期无凭证取消 | 无凭证订单取消并走既有取消／库存释放路径 | 通过；未汇款订单更新为 `physicalStatus=cancelled` 和 `importStatus=cancelled`。 |
| 待审核凭证保护 | 待审核凭证订单超过期限时不得自动取消 | 通过；待审核订单保持 `receipt_uploaded` 状态。 |
| 自动IB读取关联订单 | IB详情、成本统计、到货匹配应透过其 `cnId` 读取同一CN订单，不得用IB自身ID漏单 | 通过；IB详情读取3笔订单，IB成本利润统计订单数为3，到货匹配读取2笔未取消订单。 |
| IB锁定／解锁 | 锁定记录操作者；解锁必须有原因并留下审计 | 通过；空白原因被拒绝，有效原因解锁成功，IB审计含锁定与解锁原因记录。 |

## 回归与清理结果

专项真实演练已通过；随后已执行 TypeScript 编译与全量测试，结果为 **54个测试文件、362项测试全部通过**。演练结束后再以数据库查询复核，带有 `QA-CNIB-E2E-` 标识的客户、商品、直播、订单及CN／IB采购单均为 **0笔**，不会保留或影响任何正式数据。

> 本次实测未发现需调整的CN／IB生产逻辑缺陷。演练中修正的仅是测试适配：客户编号长度、直播倒序展示，以及DATE字段以Date对象读回的比较方式；这些不改变正式业务功能。

## 界面验证限制

服务层、真实数据库、订单关联、阶段统计、超期保护、自动IB、IB读取CN订单、审计和清理均已验证。由于后台登录会话仍不可用，尚未用鼠标点击验证CN三步骤向导的视觉交互、逐场次展开显示、CN／IB打印预览和页面按钮状态；这些界面流程应在管理员会话恢复后补做一次人工验收。

## 后续摘要增强（2026-08-12）

CN／IB页面现增加了三个实时摘要卡：**有效关联XTC订单数**（同时显示累计关联数）、**CN／IB单据数**及**最近超期处理结果**。最近超期处理结果采用新增的 `cn_expiry_run_logs` 持久化运行日志：每次定时或人工调用超期服务时都会记录检查数量、自动取消数量、失败数量、涉及订单号及执行时间，避免将“没有取消订单”误显示成“没有执行”。页面每30秒及窗口重新聚焦时刷新数据。

摘要接口若暂时失败，页面会显示明确的错误说明与“重新载入摘要”按钮，并且不会以零值误导管理员。新增日志表已由迁移0021应用；隔离演练的自动清理亦已扩展至该表，重跑真实演练并查询后，包含 `QA-CNIB` 订单号的运行日志计数为 **0**。TypeScript编译和CN／IB专项回归均已通过。
