# 心田系统｜营销中心完整管理员操作说明书

> **适用范围**：本说明以当前「营销中心」页面及已启用的 Facebook 留言／直播捉单逻辑为准。营销中心、Campaign Flow 与直播捉单会共同出现在日常营销流程中，但三者并不是同一个自动化入口；请先阅读第 2 节的边界说明，避免把「建立营销活动」误当成「开启留言自动下单」。

## 1. 营销中心可以做什么

营销中心用于管理优惠活动、优惠规则、幸运抽奖、客户分群、营销消息与投递效果。其核心用途是对已有客户做合规的营销触达，并为活动优惠、抽奖资格和投递结果保留审计记录。

营销中心内建立的活动或规则，**不会自行监听 Facebook 帖子留言、不会因为客户留言关键词就自动建立订单**。留言关键词、公开回复、私聊订单链接和直播捉单，属于 Facebook 留言／直播与 Campaign Flow 的事件处理逻辑，详见第 8 节。

| 模块 | 用途 | 会否直接建立订单 | 会否立即扣库存 |
|---|---|---:|---:|
| 营销活动 | 建立活动名称、代码与状态，作为优惠、抽奖、消息归因的容器 | 否 | 否 |
| 优惠规则 | 定义满额优惠、赠品、加价购等活动条件 | 否；在客户结账／订单应用活动时才影响订单 | 仅实体项目实际并入订单时才占用库存 |
| 幸运抽奖 | 配置奖项、查看资格、执行开奖 | 否 | 抽奖本身不扣库存；实物奖项加入原订单时才扣 |
| 客户分群 | 按客户资料筛选营销受众 | 否 | 否 |
| 营销消息／自动营销 | 向符合 Messenger 合规窗口的客户发送文字营销内容 | 否 | 否 |
| 效果分析 | 查看真实归因订单、营收、优惠与投递结果 | 否 | 否 |

## 2. 先分清三种工作：营销中心、Campaign Flow 与直播捉单

营销中心的「自动营销」是**由管理员建立规则后，对客户分群发送营销消息**；它并不解析客户留言中的商品关键词。Campaign Flow 是面向特定 Facebook Post、Reel、Video 或留言互动设计的流程配置；直播捉单则依赖正在进行中的直播场次、直播商品及商品关键词。

| 您想做的事 | 应使用的地方 | 结果 |
|---|---|---|
| 向近 30 天未购买的客户发送新品提醒 | 营销中心 → 客户分群／营销消息／自动营销 | 合规窗口内自动 Messenger；不在窗口内仅生成可人工复制的文案 |
| 客户在指定帖文留言「A1」后自动回复 | Campaign Flow／已绑定的 Facebook 内容 | 依流程设置公开回复；是否建单取决于该流程与商品按钮配置 |
| 客户在直播留言商品关键词后捉单 | 直播管理 → 直播商品与关键词 | 成功后建立订单、公开回复，并尝试私聊订单资料与结账入口 |
| 为订单设置满额优惠、赠品或加价购 | 营销中心 → 营销活动／优惠规则 | 满足规则时在订单／结账流程应用；不是留言即自动送出 |

## 3. 首页数据卡如何看

营销中心顶部有四张统计卡，只显示系统真实记录，不使用模拟数据。

| 数据卡 | 含义 | 管理动作 |
|---|---|---|
| 进行中活动 | 状态为「进行中」的营销活动数量 | 点击「营销活动」检查活动代码、规则与期限 |
| 启用规则 | 已启用的优惠或资格规则数量 | 确认规则条件与活动一致，避免优惠重叠 |
| 成功投递 | 已成功送出的营销消息数量 | 如出现失败提示，应到「最近投递审计」检查 |
| 客户分群 | 启用中的分群数量，以及启用中自动营销规则数量 | 定期检查分群条件，避免对象过宽或过旧 |

## 4. 「营销活动」分页：活动与优惠规则

### 4.1 按钮：新增营销活动

操作路径：**营销中心 → 营销活动 → 右上角「新增营销活动」**。

| 字段／按钮 | 如何填写 | 作用与注意事项 |
|---|---|---|
| 活动名称 | 使用客户和员工都能辨识的名称，例如「周末花园补给优惠」 | 用于列表、消息和效果分析显示 |
| 活动代码 | 输入唯一、简短的英文／数字代码，例如 `WEEKEND-2026` | 方便归因与内部核对；建议建立后不要随意改动 |
| 活动说明 | 写明客户可见的活动内容、对象与限制 | 仅作说明，不会自动建立商品关键词或发送消息 |
| 初始状态：草稿 | 建议先选草稿 | 草稿不应作为正式活动对外使用 |
| 初始状态：启用 | 已完成条件核对后再选择 | 只代表活动启用；仍需另外建立优惠规则或自动营销规则 |
| 建立活动 | 保存活动资料 | **不会**修改订单、库存、付款状态或向客户发送消息 |

建立后，活动卡会显示开始／结束时间、每位客户限制、总使用上限及已加入的规则。若这些栏目显示「未设定」或「不限」，代表目前没有该项限制；在对外宣传前应由管理员确认是否符合活动政策。

### 4.2 按钮：新增优惠规则

操作路径：**营销中心 → 营销活动 →「新增优惠规则」**。请先建立并选择一个活动。

| 规则类型 | 适用情况 | 操作重点 |
|---|---|---|
| 满额优惠 | 满 RM150 减 RM10 等 | 在 JSON 设置填写门槛与优惠金额，例如 `{"threshold":150,"discountAmount":10}` |
| 数量赠品 | 买满指定数量送礼 | 实体赠品仅在实际加入订单后才占用库存 |
| 第 N 件优惠 | 第二件、第三件优惠 | 在活动说明写明可用商品与限制，避免歧义 |
| 指定商品优惠 | 指定植物、花盆或肥料折扣 | 应先确认目标商品与现有特价不会冲突 |
| 分类优惠 | 指定分类折扣 | 不会因为分类就自动允许商品进入 XTC；XTC 资格仍以商品设定为准 |
| 清货活动 | 清货商品优惠 | 应确认库存与特价规则，避免重复优惠 |
| 加价购 | 符合条件后的加购品 | 实体项目加入订单时才扣库存 |
| 幸运轮盘资格 | 满足消费门槛后取得抽奖资格 | 资格建立本身不扣库存 |
| 直播抽奖 | 直播活动的抽奖资格 | 开奖后仍应核对奖品与订单资料 |

「规则设置」目前采用 **JSON 格式**。输入不是合法 JSON 时，系统不会保存。建议先复制页面示例，再只修改数值；保存前请由管理员复核门槛、金额、商品范围、叠加政策和活动期限。活动规则是价格规则，不是 Facebook 留言关键词；新增规则后不会自动在帖子留言中回复或建单。

## 5. 「幸运抽奖」分页：奖品、资格与开奖

### 5.1 选择活动与新增奖品

操作路径：**营销中心 → 幸运抽奖 → 选择活动 →「新增奖品」**。

| 字段／按钮 | 说明 |
|---|---|
| 选择活动 | 必须先选择已建立的营销活动；未选择活动时无法配置奖品或查看资格 |
| 奖品名称 | 写清客户可理解的奖项，例如「RM10 优惠券」或「免运费资格」 |
| 奖品类型 | 可选优惠券、积分、会员天数、免运费或「谢谢参与」 |
| 抽中权重 | 数字越大，系统随机开奖时相对机会越高；它不是百分比，也不是库存数量 |
| 储存奖品 | 建立奖品资料，供符合资格的客户开奖使用 |

可用奖品区会显示奖品类型、权重、剩余数量及件数。若显示数量限制，请在开活动前检查是否已正确配置。当前抽奖页面的原则是：**建立奖品与执行开奖不会先扣商品库存**；只有实物奖项被确认并入客户原订单时，才会通过统一库存服务占用库存。

### 5.2 按钮：开奖

操作路径：**营销中心 → 幸运抽奖 → 抽奖资格列表 → 对状态为 `eligible` 的资格按「开奖」**。

系统只允许对「符合资格／尚未开奖」的记录开奖。开奖后会留下完整审计记录；没有符合资格的记录时，系统会提示「没有可开奖的资格」。不要把「开奖」当作发货或扣库存动作；如奖项为实体商品，仍须按既有订单流程确认是否已成功加入订单。

## 6. 「自动营销」分页：分群、模板、自动营销规则与投递审计

### 6.1 按钮：新增分群

操作路径：**营销中心 → 自动营销 → 客户分群 →「新增分群」**。

分群只决定「谁会被纳入营销名单」，不会修改客户资料、订单、Credit 或黑名单状态。筛选条件采用 JSON。当前系统会自动排除**黑名单客户**及**已被合并到其他客户的旧客户记录**。

| 可用筛选字段 | 示例 | 含义 |
|---|---|---|
| `minSpent` | `{"minSpent":150}` | 累计消费至少 RM150 的客户 |
| `membershipLevels` | `{"membershipLevels":["member","vip"]}` | 仅指定会员等级；实际值须与系统会员等级一致 |
| `inactiveDays` | `{"inactiveDays":30}` | 最后下单距离现在至少 30 天的客户，适合召回 |
| 组合条件 | `{"minSpent":150,"inactiveDays":30}` | 条件必须同时满足 |

保存前，建议使用明确的分群名称，例如「近 30 天未消费且累计消费 RM150 以上」。若没有选择任何分群，自动营销规则会以系统可选客户为对象，但仍会排除黑名单／已合并记录，并受 Messenger 24 小时规则限制。

### 6.2 按钮：新增模板

操作路径：**营销中心 → 自动营销 → 营销消息 →「新增模板」**。

当前营销中心的消息模板是 **Messenger 文字模板**。填写模板名称和内容后保存，模板必须保持启用，自动营销规则才可使用。

| 支持变量 | 发送时显示 |
|---|---|
| `{{customer_name}}` | 客户显示名称、姓名或客户编号 |
| `{{campaign_name}}` | 关联活动名称；未关联时显示系统默认活动名称 |
| `{{shop_url}}` | 心田商城网址 |

建议文案清楚写明活动、有效期、行动方式和停止接收方式。不要在模板中承诺系统没有自动验证的库存、赠品或运费；也不要把营销消息模板当成直播得标通知或订单结账通知。

### 6.3 按钮：新增规则

操作路径：**营销中心 → 自动营销 → 自动营销 →「新增规则」**。

| 字段 | 如何操作 |
|---|---|
| 规则名称 | 写清用途，例如「30 天未回购客户－新品提醒」 |
| 消息模板 | 只能选择目前启用中的消息模板 |
| 客户分群（可选） | 选择已启用分群；不选择表示不限定特定分群 |
| 关联活动（可选） | 用于把营销投递与某个活动的效果分析关联起来 |
| 建立暂停规则 | 新规则会以**暂停**状态建立，避免误发 |

> **当前界面的重要限制**：自动营销规则建立后，页面提供「预演名单」「立即执行」和「暂停」，但当前可见页面没有「启用／恢复」或「排程」按钮。由于规则默认暂停，而「立即执行」只允许 `active` 规则使用，因此管理员不应假设新规则建立后会立即发送。应先确认管理端是否已有受控的启用／排程入口；若没有，则不能绕过暂停状态自行发送，需先补齐启用权限与排程操作后再对外使用。

### 6.4 按钮：预演名单、立即执行、暂停

| 按钮 | 会做什么 | 不会做什么 |
|---|---|---|
| 预演名单 | 计算最多 100 位符合分群条件的客户，并显示其中可自动发送与需人工处理的数量 | **不会**发送任何 Messenger，不会建单、不会扣库存 |
| 立即执行 | 仅限状态为「进行中／active」的规则；最多处理 100 位客户，并写入投递审计 | 不会解析留言关键词，不会建立订单或调整库存 |
| 暂停 | 立即停止该规则后续的自动执行 | 不会撤回已发送消息，也不会删除投递审计 |

### 6.5 什么情况下会自动私聊客户

营销中心的自动营销只有同时满足以下条件时，才会自动发送 Messenger：

1. 自动营销规则状态为 `active`；
2. 所选消息模板存在且处于启用状态；
3. 客户通过分群筛选，且不是黑名单、不是已合并的旧客户；
4. 客户有有效 Messenger ID；
5. 客户最近一次 Messenger 互动在 **24 小时内**。

若客户没有 Messenger ID、没有近期互动，或互动已经超过 24 小时，系统**不会强行自动私聊**。系统会建立可审计的「待人工复制／跳过」记录，并保留已渲染的文案供工作人员按合规方式处理。发送失败也会写入审计记录，不会静默忽略。

### 6.6 最近投递审计如何看

「最近投递审计」会显示规则编号、客户编号、渠道、时间与状态。

| 状态 | 代表什么 | 建议处理 |
|---|---|---|
| 已发送 | Messenger 已成功送出 | 无需重复发送 |
| 待发送 | 已排入发送流程或等待处理 | 稍后刷新核对最终状态 |
| 发送失败 | 平台发送失败或资料异常 | 查看错误原因，确认 Messenger 连线、客户资料与模板后再处理 |
| 手动复制／跳过 | 不符合自动 Messenger 合规窗口或重复投递保护生效 | 不要强制重发；由工作人员按允许的渠道与政策处理 |

系统会利用投递审计避免与订单通知或 AI 客服重复发送。同一营销规则对相同客户的重复处理也会受到去重保护。

## 7. 「效果分析」分页：数据口径

效果分析只汇总真实活动归因与投递审计数据。

| 指标 | 计算口径 |
|---|---|
| 归因订单 | 状态为已应用的活动归因记录所关联的订单数 |
| 归因营收 | 活动关联订单的实际金额 |
| 营销优惠 | 活动优惠金额；**不包括客户 Credit** |
| 成功投递 | 发送状态为成功的营销消息数，并附点击与转化记录 |
| 活动效果明细 | 按活动列示归因订单、营收、优惠、投递、点击与转化 |

营销优惠、运费补贴及客户 Credit 会分开记录，避免利润与报表重复扣减。实体赠品、加价购与中奖实物只有写入原订单项目时才会占用库存；营销提示或抽奖资格本身不会预扣库存。

## 8. Facebook 帖子／直播留言关键词：何时公开回复、私聊与自动建单

这是最容易与「自动营销」混淆的部分。以下逻辑发生在 Facebook 评论或直播留言进入系统时，而不是营销中心的自动营销规则执行时。

### 8.1 触发顺序

当系统接收到 Facebook 帖子评论或直播留言时，会按以下顺序判断：

1. 先检查是否命中已配置的 **Live AI Flow／Campaign Flow** 自动回复条件。若命中，该分支会按流程回复留言，然后结束处理；**不会建立订单**。
2. 若未被上述流程接管，系统解析客户留言中的关键词，并尝试匹配正在进行中的直播商品关键词；在没有活动直播间的特定场景下，才会按已绑定 Facebook 内容的 Campaign Flow／活动商品配置匹配。
3. 关键词确实匹配到可售商品后，系统再检查订单分类、商品资格、库存／预售规则及时间窗口。
4. 所有检查成功，才建立订单；系统先公开回复成功结果，再尝试以 Messenger 发送订单详情与专属结账入口。

### 8.2 什么情况下会「捉关键词并自动建单」

| 条件 | 是否会自动建单 | 结果 |
|---|---:|---|
| 直播正在进行，留言关键词准确匹配直播已上架商品，商品仍可售或已开预售 | 会 | 建立／合并符合规则的订单、公开确认，并尝试私聊订单资料与结账入口 |
| 没有活动直播间，但指定 Facebook 内容已绑定可捉单的 Campaign Flow／活动商品，关键词准确匹配 | 视该内容流程与商品设置而定 | 通过活动内容匹配后才可进入建单流程 |
| 留言命中 Live AI Flow／仅互动回复流程 | 不会 | 只做公开回复或流程动作，不建立订单 |
| 留言只有一般意向词、未匹配商品关键词 | 不会 | 在少数预设意向场景可回复一般说明；不会建单 |
| 关键词拼错、商品不在当前直播／活动范围 | 不会 | 不应建立订单；工作人员可引导客户重新留言正确关键词 |
| 商品库存不足且未开启商品级预售 | 不会 | 按留言先后处理，后续客户会收到售罄提示 |
| 中国代购商品已过直播有效期／截止条件不符 | 不会 | 回复代购已截止或不可下单提示；不建立 XTC |
| 客户为黑名单 | 不应捉单 | 由黑名单保护规则阻挡；工作人员应按客户管理政策处理 |

### 8.3 自动公开回复与自动私聊分别是什么

当关键词捉单成功时，系统会先在 Facebook 留言处给客户公开确认，例如提示已成功建立订单；随后会尝试发送私聊，内容可带订单商品、金额说明和专属结账入口。私聊是「尝试发送」而非无条件保证：Facebook 权限、客户是否可接收消息、平台限制或连线失败都会影响结果，失败应以审计记录或后台通知为准。

营销中心自动营销的 24 小时合规窗口，专门约束主动营销私聊；留言捉单后的订单沟通是另一条订单事件流程。无论哪一种，都不应把「有公开回复」理解为「一定已经收到私聊」；如客户未收到，应由管理员从订单与消息记录核对后再人工协助。

### 8.4 留言捉单成功后订单会怎样处理

成功建立后，系统会使用既有订单合并及库存规则：同一客户符合条件的未付款本地 XT 订单可按渠道合并；已付款或进入包货／发货阶段的订单会建立新单；XT 与 XTC 严格隔离。中国代购订单还必须在有效直播窗口内，且本地配套商品须在商品编辑页明确开启「允许进入中国代购订单」。

## 9. 管理员日常操作建议

1. **先定义目的**：要做客户召回，使用营销中心；要从帖子／直播留言自动捉单，使用 Campaign Flow 或直播管理。
2. **先建立草稿，再做小范围预演**：活动、规则、模板应先复核，再对少量受众试行；不要把测试文案直接投向全部客户。
3. **先检查 Messenger 合规窗口**：预演名单中出现需人工处理的客户，不代表系统故障，而是系统在保护 24 小时窗口规则。
4. **检查库存与优惠叠加**：实体赠品、加价购与实物奖项在真正进入订单时才占库存；在活动前需确保库存与价格条件正确。
5. **每天查看投递审计**：遇到发送失败、手动复制或跳过，应先核对客户资料、平台状态与合规条件，不要连续重发。
6. **避免名称混淆**：营销中心的「营销活动」不等于 Facebook Campaign Flow；如果目标是关键词自动回复或留言下单，必须额外配置内容绑定、流程／关键词与商品范围。

## 10. 上线前检查清单

| 检查项 | 确认内容 |
|---|---|
| 活动资料 | 名称、代码、说明、状态、期限、使用上限与客户限制均正确 |
| 优惠规则 | JSON 格式可保存；门槛、折扣、赠品、叠加规则与特价政策一致 |
| 抽奖 | 活动已选择；奖品、权重、数量限制与实体奖品库存已核对 |
| 分群 | 已排除不适合的客户；`inactiveDays`、`minSpent`、会员等级条件正确 |
| 营销模板 | 文案、变量、链接、有效期和客户行动说明正确；模板处于启用状态 |
| 自动营销 | 先预演；确认规则是否真正已启用；没有启用按钮时不得假设可自动发送 |
| 留言捉单 | 直播／活动内容已正确绑定；关键词、商品、库存、预售和 XTC 时间窗均已核对 |
| 发送后 | 查看投递审计、订单记录与库存流水；失败或未私聊成功时再人工跟进 |
