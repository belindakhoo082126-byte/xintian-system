# Campaign 与营销中心操作说明

本文说明心田系统内 **Campaign 管理** 与 **营销中心** 的用途、配置顺序及安全操作边界。两者用途不同：Campaign 用来管理某一个 Facebook 内容推广主题与其自动回复流程；营销中心用来管理优惠、抽奖、客户分群、消息模板、自动营销和投递审计。

> 所有客户消息均应以客户同意接收、平台政策及实际 Messenger 互动窗口为前提。系统会将不适合自动私聊的对象转为可审计的人工处理文案，而不会将其当作已发送。

## 一、Campaign 管理

### 1. 适用场景

当一个 Facebook Post、Reel 或 Video 需要围绕同一主题回复留言、展示商品、引导客户行动并追踪订单成果时，建立一个 Campaign。例如「八月肥料促销」可作为一个 Campaign，并在其中绑定多则相关贴文或影片。

| 项目 | 用途 |
| --- | --- |
| Campaign 名称 | 让管理员识别活动主题；建议带有月份、商品或直播名称。 |
| 内容 ID | 绑定到该活动的 Facebook Post、Reel 或 Video；同一活动可以绑定多个内容。 |
| 自动回复 | 设置客户留言后可收到的基础回复内容。 |
| 流程 | 按文字、图片、影片、商品介绍或按钮编排引导内容。 |
| 按钮 | 为客户提供后续动作入口，例如查询、选购或联络。 |
| 统计 | 查看自动建立订单数、合并订单数、商品数量及订单金额。 |

### 2. 建立与启用步骤

1. 进入后台菜单 **FB Campaign**，点击「新增 Campaign」。
2. 在「基本设置」填写活动名称、自动回复开关、自动回复文字及 Messenger Flow 开关，然后先储存。
3. 储存后打开「内容 ID」分页，加入同一推广主题的 Facebook Post、Reel 或 Video。Facebook 连结由内容绑定统一管理，不必在基本设置重复填写。
4. 在「流程」分页依序加入文字、图片、影片、商品介绍或按钮。先以客户角度检查文字、商品价格和连结。
5. 在「按钮」分页设定客户下一步动作，并核对不会导向错误页面。
6. 先保留「草稿」进行内部检查；确认内容、商品和自动回复无误后，点击「开始」切换为「启用」。

### 3. 生命周期与查询

Campaign 有 **草稿、启用、已结束、已封存** 四种状态。草稿可继续编辑而不执行；启用才会进入自动流程；已结束会停止新自动流程但保留历史；已封存用于长期保留记录，并可在需要时恢复。列表上方可按 All、Active、Ended、Archived 筛选，并用名称、类型或 Facebook 连结搜索。

> 「封存」不等于删除。封存会保留历史内容、统计和审计；删除仅应在确定为错误、且不再需要保留记录时使用。

### 4. 复制与检查

「复制」会复制活动结构，适用于月度重复促销。复制后务必逐项更新名称、内容 ID、流程文案、商品、有效日期与价格。开始前应使用测试留言确认：活动被识别、客户回复正确、订单来源正确、商品库存可用，且没有重复发送。

## 二、营销中心

营销中心分为 **营销活动、幸运抽奖、自动营销、效果分析** 四个分页。实体赠品、加价购和奖品并不会因「建立活动」或「开奖」而直接扣库存；只有客户实际将项目加入原订单时，系统才会经过既有库存服务占用库存。

### 1. 营销活动与优惠规则

操作顺序为「先建立活动，再建立规则」。活动可设定活动代号、说明、起止时间、每位客户使用上限、总使用上限及是否在商城展示。规则可用于折扣、满额优惠、赠品或其他后台已提供的促销类型；建立后应检查规则名称、门槛、适用对象、叠加方式及有效期间。

| 检查点 | 管理建议 |
| --- | --- |
| 起止时间 | 先确认马来西亚时间，避免活动提前或延后生效。 |
| 使用上限 | 限量优惠应同时设定每客与总上限。 |
| 商城展示 | 只开启已完成商品、库存及文案检查的活动。 |
| 叠加规则 | 对同一订单预先测试是否可叠加，避免意外重复优惠。 |
| 库存 | 实体赠品/奖品真正加入订单时才占库存，仍应预留足够库存。 |

### 2. 幸运抽奖与直播抽奖

先在某一营销活动内建立奖品，再确认奖品类型、权重、数量上限及实体商品数量。符合门槛的客户会产生「抽奖资格」，管理员对某一资格点击「开奖」后，系统保留完整审计。开奖前不会扣实体奖品库存；客户领取且奖品合并至原订单时，才会实际占用库存。

建议先用内部测试客户核对资格条件、奖品数量上限和中奖文案。若奖品为实体商品，也须确认该商品未被停用，且库存可售。

### 3. 客户分群、模板与自动营销

自动营销的安全顺序是：

1. 建立 **客户分群**，例如按客户类型、回购条件或互动状态定义受众。
2. 建立 **营销消息模板**。模板应清楚说明活动、期限、适用条件与退订/联络处理方式，不应混入订单付款、物流或退款通知。
3. 建立 **自动营销规则**，关联活动、分群和模板。新规则默认「暂停」，不会立即发送。
4. 点击「预演名单」。预演只显示符合条件人数，不发送任何消息，应先检查受众是否正确。
5. 确认后才启用规则；可按需要点击「立即执行」或使用已绑定的排程。
6. 在「最近投递审计」查看发送成功、失败及人工回退结果。

系统会判断 Messenger 合规互动窗口。若近期没有合规互动窗口，系统不会自动私聊，而是生成可审计的人工发送文案。人工处理不应被误记为自动发送成功。

### 4. 效果分析与失败处理

营销中心顶部会显示进行中活动、启用规则、成功投递及客户分群概览。「效果分析」用于查看活动结果；应以已保存的投递审计、订单和活动记录为准，而非只看即时卡片数字。发送失败或需要人工处理时，应打开相关投递记录，核对客户、模板、规则、失败时间与原因，再决定重试、人工发送、暂停规则或修正模板。

## 三、与订单、AI通知及库存的边界

| 功能 | 正确归属 |
| --- | --- |
| 营销推广、优惠、抽奖、客户召回 | Campaign 与营销中心 |
| 付款、结单、物流、退款等订单事务通知 | 订单通知流程 |
| 自动通知发送失败与人工重发审计 | AI 通知中心 |
| 客服问答、转人工与知识库 | AI 大脑/AI 客服 |
| 实体商品的库存变动 | 只有订单真正建立、赠品/奖品加入订单或经库存操作后才变动 |

营销消息不得替代客户的订单付款、退款或物流通知。若发现自动营销与订单通知使用了相同客户、相近时间或相同内容，应先暂停营销规则，再从投递审计和 AI 通知中心分别核对，避免重复发送。

## 四、上线前检查清单

- [ ] Campaign 名称、内容 ID、自动回复、流程与按钮已逐项复核。
- [ ] Campaign 从草稿切换为启用前，已用测试留言验证。
- [ ] 营销活动的日期、资格、门槛、上限和叠加方式已核对。
- [ ] 抽奖奖品的数量上限与实体库存已确认。
- [ ] 自动营销规则已先预演受众，未直接对未检查名单发送。
- [ ] 已确认模板不会与付款、物流、退款或 AI 通知重复。
- [ ] 已检查最近投递审计中的失败及人工回退记录。
- [ ] 活动结束后改为「已结束」或「已封存」，保留可追溯历史。
