# 心田营销中心实施设计

## 目标与边界

营销中心独立管理**促销活动、客户召回、营销消息与活动效果**。它不接管既有的新订单、付款、付款审核、发货、追踪号码、会员入群或 AI 转人工通知；这些通知继续由订单、会员、系统设置和 AI 客服模块负责。

每项优惠必须归属于一场营销活动。活动支持草稿、待开始、进行中、暂停和已结束状态，并按订单类别、下单来源、客户群、活动时间、可叠加条件与客户／订单使用次数限制判定是否可用。

## 现有能力与复用原则

| 领域 | 已有能力 | 营销中心的接入原则 |
| --- | --- | --- |
| 下单与库存 | `reserveProductStocksForOrder` 在单条条件更新中扣减库存，防止并发超卖 | 所有收费商品、赠品、加价购和实际中奖实体奖品都必须经同一服务占用库存；未中奖和未解锁资格不能扣库存。 |
| 订单价格与运费 | `createOrderWithSplit` 已保存订单级促销字段，并以优惠后商品金额计算免邮门槛 | 营销计算在创建或更新订单前得到最终商品价格、赠品、加价购与订单级折扣；西马 RM150 正式免邮规则保留。 |
| 成本与利润 | 订单项目已保存 `unitCost`、`originalUnitPrice`、`discount` 与 `subtotal`，正式商品走 FIFO 成本分配 | 新增项目级营销来源及优惠快照，以销售实收、商品／赠品／奖品成本、运费承担与退款进行活动归因；Credit 只作为付款方式，不重复当作折扣。 |
| 客户分群 | 客户表已有会员层级、消费次数金额、最近下单日期、Credit、黑名单与来源字段 | 先复用已有可审计字段形成分群，后续新增营销标签／订阅偏好和消息点击追踪。 |
| 定时任务 | Heartbeat 已在项目中可用且现有安全回调已注册 | 定时营销使用受身份验证、按任务 UID 查询、可暂停和幂等的 `/api/scheduled/` 回调；不得使用常驻计时器。 |

## 关键业务不变量

1. 营销赠品、加价购和抽中实体奖品必须保存至原订单项目；赠品价格为 RM0，但成本仍计入订单与活动利润。
2. 订单取消、删项或减少数量时，营销商品必须和普通商品一样释放库存；发货时仅将已占用数量转为已完成，不得重复扣库存。
3. 会员资格在订单成立时实时校验；已成立订单保留当时营销价格，取消后重建订单按届时资格重算。
4. 固定流程顺序为：读取基础价格与会员资格 → 检查活动适用性与次数限制 → 计算商品优惠及赠品／加价购 → 原子占用库存 → 保存价格与成本快照 → 记录营销使用与投递审计。
5. 轮盘资格只有在金额达标、全额付款、审核通过、订单未取消且未过期时可解锁；实际抽中实体奖品才占用库存。

## 分阶段交付

第一阶段先建立活动、规则、订单归因、客户分群、消息投递与抽奖资格的数据基础，再将统一营销计算服务接入订单创建／编辑和商城展示。所有涉及营销自动发送的规则初始均处于暂停状态，必须由管理员明确启用。
