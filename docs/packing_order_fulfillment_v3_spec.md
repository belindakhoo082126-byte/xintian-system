# 包货、订单与库存联动规格（实施摘要）

> 来源：用户上传的 `pasted_content_2.txt`。本摘要只固化业务约束，不替代现有订单、库存、退款及审计记录。

## 1. 包货异常与等待补货

- 异常必须以**订单商品／规格／数量**为粒度，支持缺货、破损、品质问题、延迟、取消／退款等原因。
- 异常不可直接删除；需以已处理、关闭或取消等可审计状态结束，并显示处理人、处理时间和关联订单。
- 等待补货须保留缺货数量、商品、状态、预计到货／备注；补货入库后仅分配给等待补货的数量，并提示恢复发货。
- 有开放异常、等待补货、未发完发货批次、退款处理中或明确保护标记的订单，不得被自动取消。

## 2. 部分发货与发货批次

- 每次发货按**商品／规格／数量**创建可追溯发货批次；同一订单可分多批发出。
- 每项须能清楚显示已发数量、待发数量及关联批次，且不得超发。
- 包裹、快递、运单、重量、通知和订单状态须与该发货批次一致；全部商品发完后才成为已发货／已完成。

## 3. 退款与库存

- 包货异常的退款必须关联正式退款记录，避免重复处理。
- 仅在退款实际完成时处理库存：可售退库、报损、不影响库存或待退货确认；所有动作须产生库存流水。
- 退款、库存、订单状态与利润调整均须可追溯，不得以直接覆盖旧记录的方式修正。

## 4. 订单拆分、合并与合并邮寄

- 拆单以商品／规格／数量为单位，产生新订单号，并保持每张订单独立金额、库存、付款、状态和审计。
- 合并订单／合并邮寄仅允许同一客户的兼容订单；合并后仍保留来源订单、独立金额与库存事实，使用统一包裹／运单执行邮寄。
- 订单已发货、已完成、已取消、关闭或有受保护处理时，禁止不安全的取消、合并、拆分或加单动作。

## 5. 加单权限与界面

- 只允许待汇款、部分汇款、保留、待审核付款凭证和待备货订单加单；其他关闭或履约完成状态禁止加单。
- 包货工作区、商品表格、异常与操作对话框须扩大，关键状态要清晰可读；手机端必须可完成关键操作。

## 6. 现有数据基础（初步盘点）

- 已存在 `order_exceptions`、`order_exception_items`、`order_exception_replacements`、`packages`、`package_items`、`shipments`、`order_refunds`、`order_refund_items` 和 `inventory_adjustments` 表。
- 当前订单已有 `parentOrderId`，包裹已支持多包裹与逐订单项数量；后续优先扩展既有模型，避免平行、重复的库存和退款账本。
- 自动任务改造将沿用已有 Heartbeat 机制，不引入常驻脚本或重复调度器。
