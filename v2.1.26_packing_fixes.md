### Issue 4: West Malaysia shipping calculation error
- **Problem**: User says 12kg should charge RM6 (2kg excess × RM3), 15kg should charge RM15 (5kg × RM3) for free shipping orders
- **Current code**: `calculateNormalShippingFee` (line 7570) and `calculateWestMalaysiaShipping` (line 5661) both look correct:
  - Free shipping (>=RM150): 0 base + excess × 3
  - Non-free: 15 base + excess × 3
- `processActualWeight` (line 7711) calls `calculateNormalShippingFee(itemsSubtotal, actualWeightKg)` - this should be correct
- BUT: `processActualWeight` has `needsSpecialOrder` condition: `Math.abs(difference) > 0.01 && actualWeightKg > 10` - this means if actual weight ≤ 10kg, no special order even if there's a difference. This is correct behavior for free shipping (≤10kg = free).
- **BUT**: The issue might be that `processActualWeight` uses `itemsSubtotal` but should use `physicalSubtotal` or check the actual order's free shipping status
- **Actually**: The real issue is that `processActualWeight` compares `actualShippingFee - customerPaidShipping`. If customer paid 0 (free shipping, >=RM150) and actual weight is 12kg, actual fee = 0 + 2×3 = RM6, difference = 6-0 = 6, needsSpecialOrder = true (weight > 10). This seems correct.
- **Wait**: User says "10kg内没有收取运费" - for free shipping orders, first 10kg is free. If 12kg, charge RM6. If 15kg, charge RM15. This IS what the code does.
- **The real issue might be**: The `needsSpecialOrder` condition `actualWeightKg > 10` means if weight ≤ 10, no special order even if there's a difference. But for non-free shipping (order < RM150), if actual weight is 8kg, actual fee = RM15, customer paid RM15, difference = 0, no special order. This is correct.
- **Actually the issue might be**: `processActualWeight` is called with `itemsSubtotal` from `order.physicalSubtotal`, but the free shipping threshold check in `calculateNormalShippingFee` uses `nonSpecialSubtotal !== undefined ? nonSpecialSubtotal : itemsSubtotal`. Since `processActualWeight` doesn't pass `nonSpecialSubtotal`, it uses `itemsSubtotal`. This should be fine as long as `physicalSubtotal` is the right value.
- **Conclusion**: The calculation logic seems correct. The issue might be that the packing detail doesn't DISPLAY the correct customer paid shipping or the actual shipping fee breakdown. Need to verify the display in PackingDetail.tsx.

### Issue 5: Exception handling cannot save

### Issue 6: A5 print overlaps with language translation
- **Problem**: When printing A5, the language translation toggle/content overlaps
- **Root cause**: `index.css` (line 235-247) only defines `.no-print` but NOT `.print-hide` and `.print-only` which are used in PackingDetail.tsx
- **Fix**: Add `.print-hide { display: none !important; }` and `.print-only { display: block !important; }` to `@media print` in index.css, and `.print-only { display: none; }` outside media print
