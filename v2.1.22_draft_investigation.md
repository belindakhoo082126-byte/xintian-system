# V2.1.22 草稿订单/订单变更请求调查笔记

## 数据库表结构

### draft_orders表 (schema.ts 2679-2709)
- id, draftNumber, customerId, customerName, messengerId, platform
- aiLogId, detectedIntent, originalMessage, items(JSON), totalAmount
- status: enum ["waiting_approval", "approved", "rejected", "expired"]
- approvedBy, approvedAt, rejectedBy, rejectedAt, rejectReason
- officialOrderId (批准后关联正式订单)
- createdAt, updatedAt

### order_change_requests表 (schema.ts 2715-2747)
- id, requestNumber, orderId, orderNumber, customerId, customerName
- requestType: enum ["add_item", "remove_item", "change_quantity", "change_address", "change_phone", "cancel_item", "other"]
- changeDetails (JSON), aiLogId, detectedIntent, originalMessage
- status: enum ["waiting_approval", "approved", "rejected", "expired"]
- approvedBy, approvedAt, rejectedBy, rejectedAt, rejectReason
- createdAt, updatedAt

### reservation_records表 (schema.ts 2755-2777)
- productId, productName, variantId, quantity
- source: enum ["draft_order", "change_request"]
- referenceNumber, referenceId
- status: enum ["active", "converted", "released"]

## 后端逻辑 (server/businessAi.ts)

### approveDraftOrder (line 319-374)
- 检查status=waiting_approval
- 生成订单号: `XT${10000 + count + 1}` (5位)
- 创建正式order: orderType="physical", physicalStatus="pending", paidAmount="0"
- 创建orderItems from draft items
- convertInventory
- 更新draft status="approved", officialOrderId

**问题**: 
1. 只创建XT(本地)订单，没有判断orderCategory(本地/中国代购)
2. physicalStatus="pending"(待汇款)，中国代购应该是"hold_order"(挂单)
3. 没有使用createOrderWithSplit函数
4. 没有设置orderCategory字段

### approveOrderChangeRequest (line 476-553)
- 检查status=waiting_approval
- 根据requestType执行不同操作:
  - add_item: 插入orderItems, convertInventory
  - remove_item: 删除orderItem
  - change_quantity: 更新orderItem数量
  - change_address: 更新orders.shippingAddress
  - cancel_item: 删除orderItem
- 重新计算totalAmount = sum of items.subtotal
- 更新request status="approved"

**问题**:
1. 重新计算totalAmount但没有调用recalculateOrderBalance
2. 没有重新计算付款状态(paidAmount vs totalAmount → partial_payment)
3. 没有检查原订单状态是否允许修改
4. totalAmount计算没有考虑折扣/额外收费/Credit/运费

### rejectDraftOrder (line 379-395)
- releaseInventory
- 更新status="rejected"

### rejectOrderChangeRequest (line 558-569)
- releaseInventory
- 更新status="rejected"

## 需要修改的内容

### 1. 取消过期机制
- schema.ts: 移除status enum中的"expired"（或保留但不再使用）
- 前端: 移除"已过期"筛选选项
- 新增"已失效/无法执行"状态（当原订单已发货/完成/取消时）

### 2. 新订单审批逻辑
- approveDraftOrder需要:
  - 判断orderCategory (本地/中国代购)
  - 本地: physicalStatus="pending"(待汇款)
  - 中国代购: physicalStatus="hold_order"(挂单)
  - 设置orderCategory字段
  - 不可重复生成(检查officialOrderId已存在)

### 3. 订单变更请求审批逻辑
- approveOrderChangeRequest需要:
  - 检查原订单状态是否允许修改
  - 批准后直接修改原订单(已有逻辑)
  - 不重置原订单状态(保留physicalStatus)
  - 调用recalculateOrderBalance重新计算付款状态
  - 不建立新订单(已有逻辑)

### 4. Dashboard同步
- 修复DraftOrderCount/ChangeRequestCount使用真实count
- 点击跳转带?status=waiting_approval参数
- 前端页面读取URL query自动设置筛选

### 5. 筛选改为: 全部/待审批/已批准/已拒绝
- 移除"已过期"选项
- 前端和后端同步修改
